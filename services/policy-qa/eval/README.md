# 评测

两层,分开是因为成本差三个数量级。

| | 跑什么 | 花钱 | 在哪跑 |
|---|---|---|---|
| `retrieval.py` | 检索层能不能把该看的政策捞出来 | 否 | pytest 门禁 + 手动跑真 vault |
| `answers.py` | 模型答题守不守纪律 | **是**(真 DeepSeek) | 手动 |

分层的理由:模型再聪明,检索不出来就无从谈起。检索层可以确定性地量化,那就单独量化、
免费跑、进门禁;答案质量才需要花钱。

## golden 从哪来

`golden/2026-07-monthly.json` 抄自 2026 年 7 月能源政策月刊成品的「政策速览」两张表。
那期是**人工选目**——编辑通读候选池后判断哪些会改变加油/充电/电力三块业务的决策。
所以它是现成的、有业务含义的标准答案:这 14 篇就是"该被检索到"的。

`golden/disciplines.json` 每一条都对应一个**真踩过的坑**,不是假想:文号编造、撞车 pid
的缺陷未转述、把成品油调价当重要政策、给库外文件编内容、推算附件里的数字。

## 跑检索评测

```bash
python eval/retrieval.py "/path/to/policy-vault"
```

输出每条选目被哪几种检索姿势捞到。**关注点不是总召回率,而是"只被一种姿势捞到"的条目**
——那说明它很脆弱,换个问法就漏了。

2026-08-17 基线:14/14。但这个数字是**加了两条针对性姿势之后**才有的,加之前是 12/14:

- 「节能降碳行动计划」只有**放宽窗口±30 天**才捞得到。库里 date 是 2026-06-26(成文日),
  月刊记的是 07-10 发布。掐着月份边界查必漏。
- 「车船税」只有**按机关扫**才捞得到。两份记录都被打成 INFO(D1=1 / D1=2),月刊人工给 3 分。
  跨条线财税件打分失准,按重要性排序会沉到 50 名开外。

这两条已经写进 system prompt 的盘点式检索纪律——评测发现的东西必须回流到 prompt,
否则只有评测知道、模型不知道。

顺带查出一个检索层真缺陷:`issuer` 字段全库 38% 为空(机关只写在标题里),
只匹配 issuer 列会静默漏掉三分之一的库,并诱导模型做出"库里没有财政部的文件"这种
假全称否定。已改成 issuer 与 title 任一命中。

## 跑答案评测

```bash
POLICY_QA_DATA_BACKEND=vault POLICY_QA_VAULT_DIR="/path/to/policy-vault" \
POLICY_QA_ACCESS_TOKEN=x DEEPSEEK_API_KEY=sk-... \
python eval/answers.py [用例id ...]
```

不带参数跑全部;带 id 只跑指定几条(省钱)。

子串匹配是粗的,**刻意如此**:这些纪律的失败表现都很具体。粗匹配挡住明显回归,
标了 `note` 的用例必须人眼复核,报告末尾会列出来。

2026-08-17 首轮:8/8 断言通过。人眼复核的两条也过了——
「附件数字」那条模型给了具体价格,回原文逐字核对,四个数字全部对上,无编造。

## 加新用例

发现新的失败模式就往 `disciplines.json` 加一条,`why` 字段写清楚**它是怎么被发现的**。
这个文件的价值在于它记录的是真实事故,不是想象中的风险——写 why 是为了让后来的人
知道这条断言不能随便删。
