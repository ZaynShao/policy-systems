# 演示数据

月刊产线离线演示页面用的数据,2026-11-19 整理。四期都是真实发出去的能源政策月刊(2026 年 7–10 月),
是我用月刊 skill(`skill/energy-policy-monthly/`)在本机出的稿。这里把每期的终稿正文转成平台新版月刊的格式
(`monthly.v2`,也就是 `src/views/monthly/monthly-content.ts` 认的那套),再包成月刊接口返回的样子。

生成离线页面:在 `services/heng-guan/frontend/` 下 `npm ci`,再 `node build-offline.mjs monthly`,得到 `dist/monthly.html`。

## 怎么转的

skill 出的终稿是 markdown(`## 一、概述` 这种),产线(`services/policy-pipeline/scripts/l3_monthly/`)只有
content → 终稿的组稿(`assemble.build_final_md`),没有反方向,所以写了一个一次性的小转换(只在整理数据时用,没放进仓库)。规则:

- 文字原样,只去掉 markdown 的 `**` 加粗符(新版页面一律按纯文字显示);段落之间空一行,列表项各占一行。
- 概述:「与公司三大业务的关联速判」之前的几段 → `overview`;三条速判 → `businessTakes`
  (业务名取「X业务」的 X;7 月刊电力那条标签里带的「（储能·V2G·交易）」放在正文开头)。
- 政策速览:国家级表 → `quickTable`(level 国家级;文件格末尾的「（文号）」拆进 `doc_no`,一格里有两份文件的不拆)。
  地方表也并进 `quickTable`:level 地方、打分留空、「区域」放在发文机关那一列;地方表的「关键词」「公司业务关注」两列
  新版格式没有对应字段,没收(地方政策综述正文里有相应的叙述)。
- 政策详情:(一)(二)… → `details`(编号 01 起;标题保留终稿里带的发布日期;「关键词」那一行放在 `info` 开头;
  【政策信息】【政策解读】【重点关注内容】→ `info` / `reading` / `focus`;决策建议 → `advice`)。
  终稿的决策建议不带行动标签(标签写在重点关注内容各条末尾),`tag` 留空,所以页面上业务名后面会多一个「·」。
  最后一节「地方政策综述」→ `localRoundup`。附录 → `appendix`。
- 新版格式有、终稿没有的,一律留空:`narrative`(本月定调)、`policyId`(没有对应的平台政策,详情标题不带原文链接)、
  `caveats`(这几期是走完三路审计、人工裁决后发出的,没有残留,所以不出容错提示条)、`uncovered`(漏采件写在终稿附录里)。
- 没带过去的几行:刊头标题、政策详情章首那句「按重要性由高到低，国家级在前。」、附录小标题「值得提前关注的政策动向」
  (新版页面的章节名由页面按有内容的段自己生成)。
- 外层字段:标题、封面日期照产线投影进平台时的写法(`scripts/l3_monthly/project_pg.py`:「能源政策月刊 · 2026 年 N 月」、
  每月 1 日);发布日期取各期发布版 docx 封面;状态「已发布」、版本 1。

## 核对

- 用产线自己的组稿函数 `assemble.build_final_md` 把四期反排回终稿形状,终稿每一行正文都在(表格逐格核,地方表那两列除外)。
- 用产线 D 门的规则(`gates.check_style` 里的 D-EMPH、D-MD)按段扫,四期都没有 markdown 残留。
- 离线页面在 jsdom 里跑过:四期都能打开,章节一到五连编,详情篇数和速览表行数对得上,
  提交修改意见、超长意见被拒、换期都正常。
