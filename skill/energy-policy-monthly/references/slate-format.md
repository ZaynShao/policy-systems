# slate.json 格式

选目的产出，`pack_build.py` 的输入。

## 骨架

```json
{
  "task": "2026-07月刊",
  "title": "能源政策月刊 2026年7月",
  "window": {"lo": "2026-07-01", "hi": "2026-08-06"},
  "national_detail": [ ... ],
  "local_detail": [ ... ],
  "roundup": [ ... ],
  "appendix": [ ... ]
}
```

## 详述件字段（national_detail / local_detail）

```json
{
  "pid": "P_2026_NDRC_1077",
  "title_hint": "第四监管周期省级电网输配电价",
  "file": "关于第四监管周期……(发改价格〔2026〕1077号).md",
  "raw_issuer": "国家发展改革委",
  "raw_docno": "发改价格〔2026〕1077号",
  "raw_dateline": "2026-07-08",
  "raw_pubdate": "2026-07-10",
  "companions": ["P_2026_XX_..."],
  "editorial_score": "编辑评分5分(机器打分层漏评)",
  "why": "为什么选它——要写清楚对哪块业务、改变了什么",
  "dq": ["价表在未采附件,具体价位不可引", "同 pid 采到 2 份"]
}
```

- `raw_*` 四个字段是**核过原文的结果**，不是 frontmatter 抄来的。`raw_dateline` 是落款日，`raw_pubdate` 是发布日，两者常不同。
- `title_hint` 消 id 撞车用，写清号数或日期（如"江苏2026年第12号(7月3日)"），`pick_file()` 靠里面的号数/日期匹配文件。
- `companions` 放同源伴随件（如某园区项目的方案、纳规、优选三件），装配时并入同一 bundle。
- `editorial_score` 只在编辑改分时写，记明是漏评补分还是失准上调。
- `dq` 逐条记数据坑，写作时据此避让。

## roundup 组

```json
{
  "key": "输配电价省级落地",
  "title_hint": "第四监管周期输配电价省级落地综述",
  "members": [
    "P_2026_GZ_FGW_421",
    {"pid": "P_2026_JS_FGW_10", "title_hint": "江苏2026年第12号(7月3日)"}
  ],
  "why": "……",
  "dq": ["甘肃一条为新闻稿而非文件正文,只作节奏佐证不引条款"]
}
```

`members` 可以是裸 pid，也可以是 `{pid, title_hint}` 对象——**同一组里出现 pid 撞车时必须用对象形式**。

## 剔除标记

编辑指令剔除某组时不删条目，标记留档：

```json
{
  "key": "成品油调价",
  "excluded": true,
  "excluded_reason": "编辑指令(2026-08-06):油价变动类内容整体退出政策分析范围",
  "members": [ ... ]
}
```

`pack_build.py` 会跳过装配，但在 INDEX.md 里记一行说明。

## appendix

```json
[
  {"key": "已知漏采", "items": ["《X规划》(机关,日期)——库中未采,业务相关度高,建议补采", ...]},
  {"key": "数据质量", "items": ["本窗口 N 条候选中 M 条正文乱码,已在读取侧还原", ...]}
]
```

漏采项来自 web 查漏。按纪律这些**只记漏项、不据此写正文事实**，但要让读者知道简报的边界。

## 2026-08 起新增的约定

**内部件 pid**：`INTERNAL_<机关缩写>_<YYYY-MM>`（如 `INTERNAL_XXX_2026-08`），`file` 写 `internal/` 下的相对路径。`pack_build` 对它会提示"vault 无此 pid 的 RAW 文件"，属预期，写作直接读 internal/ 原件。纪要类内部件的 dq 必须记：非官方文本、数字为口头口径标"据交流"、不点名个人、拜访日期有无、与上期内部件如何互证、预告未兑现要写"截至发稿未见"。

**补采件**：详述件可带 `"supplement": ["supplement/<文件>.md"]`，指向用户裁定补采的公开材料（答记者问、解读）。补采文件本身要有 frontmatter 记 `source`、`url`、`fetched_at`、`note`（为什么补、成品怎么标注）。

**跨月件**：`scan_window` 捞回的 ↩ 件入选时，dq 第一条写"frontmatter date 为成文日 X，Y 月才公开，跨月捞回"，`raw_dateline` 与 `raw_pubdate` 都填。

**appendix 条目标签**：web 查漏来的加前缀【web查漏】，省级动态加【web查漏·省级】，核实为"无事件"的判断加【web查漏·结论】；库里有线索但正文未采的（外来文号指向的文件、报道提到的文件）直接写文件名加"库中未采，建议补采"。

**用户裁定**：选目停点后用户的裁定逐条写进顶层 `note`（一句话）和 `选目说明.md` 的"裁定记录"节（表格：裁定 | 处置）。降级的件不删，移到 roundup 并在 why 里写"编辑裁定（日期）由…降为…"。

**editorial_score 写法实例**：
- `编辑评分5分(机器打分层无此件产出,旗舰件漏评补分)`
- `编辑评分4分(机器1-2分,旗舰规划失准上调;加油线唯一的五年基准文件)`
- `编辑评分3分(机器1分,跨条线执法件失准上调;web查漏点到、回库核实已采,frontmatter date 误标致漏扫)`
- `编辑评分5分(内部件,打分层未见;电力线提前量信号最强的一件)`
