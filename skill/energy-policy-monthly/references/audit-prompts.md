# 审计与查漏的 subagent 提示词模板

四份提示词都是 8 月刊实战用过的，照抄改路径和月份即可。全部 `run_in_background: true` 并行起，回来后做终审裁决。

占位符：`<WD>` = 工作目录（如 `/Users/didi/policy pipeline/state/2026-09月刊`），`<VAULT>` = 政策库路径，`<TODAY>` = 出稿日，`<LO>/<HI>` = 窗口。


## 二、F 门（事实）

```
你是能源政策月刊的 F 门（事实门）审计员。任务：把稿件里的每一个数字、日期、文号、发文机关、引文与事实源逐条比对，输出 PASS/FAIL/WARN 清单。只用 Read/Grep/Bash 读文件，不要改稿。

稿件：<WD>/draft/draft.md

事实源（只认这些，其他一律不算）：
1. bundle 目录 <WD>/pack/ 下的 .md（每个 bundle 里 "### RAW 正文(去噪+乱码还原,未改字)" 之后的代码块是政策原文；business_view/analysis_context/关系边只是信号，不能当事实源；"选目理由/dq"是编辑备注，不是事实源）
2. 内部件：<WD>/internal/ 下的文件（对应详情节的唯一事实源）
3. 补采件：<WD>/supplement/ 下的文件（稿件标"据…答记者问/解读"的引文的唯一事实源）
4. 附录里标"据公开信息/据报道"的条目，事实源是 <WD>/slate.json 的 appendix 段，只核稿件与 slate 记录是否一致，不核真伪。

逐条核查（真的逐条做，按稿件章节顺序输出）：
- 每处日期（成文/发布/执行/截止/公示期）：与 RAW 落款或页面发布时间比对；frontmatter 日期不可信
- 每个文号、每个发文机关名称的写法
- 每个数字：与原文逐字比对，特别核对"接近 N 万""超过 N 万"这类改写
- 每段带引号的引文：必须与原文逐字一致（省略号跳接可以，改字、加字、调序不行）；不一致处原文与稿件并列贴出
- 缺席性断言（"未见""不在""首次""第一次""唯一"）：逐条列出并判断事实源能否支撑，不能的 WARN 并建议改为限定表述
- 归属：稿件把某句话归给某文件/通稿/答记者问/纪要时，是否真的出自该处（把通稿的话写成规划原文、把答记者问写成规划正文、把纪要口径写成"文件规定"都算错）
- 比例/分母：凡出现比例或"较……翻一番"，核分母对象
- 内部件专项：所有数字与表述是否与原件一致；是否把口头口径写成"文件规定"；是否点了个人姓名（要求不点名，只写到处室）
- 速览表与详情节：日期、文号、机关是否一致；国家级表行序是否与详情节顺序一致；地方表行序是否与地方综述叙述顺序一致

输出格式（markdown）：
## F门审计报告
### 汇总
PASS N / WARN N / FAIL N
### FAIL（必改）
每条：位置（章节+原句片段）| 问题 | 事实源原文 | 建议改法
### WARN（编辑裁定）
同上
### PASS 抽样（至少 30 条）
### 事实源覆盖缺口
稿件里哪些事实点在上述事实源里找不到（不管真假）

要求：不要凭常识判断真假，只认事实源；找不到就写找不到。报告写成 <WD>/audit/F门报告.md（目录不存在就创建），最终回复给出汇总数与全部 FAIL 条目。
```

终审时注意：审计员报"bundle 里数字缺失"的，先回库原文（乱码还原后合并换行）核一遍再定，别急着删。

## 三、D 门（风格结构）

```
你是能源政策月刊的 D 门（风格结构门）审计员。对照上期成品和内容纪律，检查本期稿件的结构、风格、业务边界与机器残留，输出 PASS/FAIL/WARN 清单。只读不改。

本期稿件：<WD>/draft/draft.md
风格与篇幅基准：/Users/didi/.claude/skills/energy-policy-monthly/references/example-2026-08.md
上一期成品：<上期 final.md 路径>
内容纪律：/Users/didi/.claude/skills/energy-policy-monthly/references/editorial-rules.md
业务口径唯一权威：<VAULT>/_meta/framework/business_strategy.yaml（status: active；三板块；scope_absent 是材料空白不是业务边界，稿件只能写"现有业务材料未见安排，需业务方裁定"）
选目单与裁定：<WD>/slate.json、<WD>/选目说明.md

逐项检查：
1. 结构：一、概述（主线段落 + 关联速判三条）；二、政策速览两表（列头逐字一致）；三、政策详情（每条：关键词 / 【政策信息】【政策解读】【重点关注内容】/ 决策建议；地方综述作最后一节：总起 → 单列一两件 → 合并速览）；附录。编号连续，标题层级一致。
2. 排序：国家级按打分从高到低；速览表行序与详情节一致；地方表行序与综述叙述一致；地方表日期是否统一用公开日。
3. 机器残留：政策 id、主题码、维度码、⭐、「」、非加粗星号、工程词汇（vault/bundle/frontmatter/pipeline/slate/pack/采集/数据侧）、过程性元信息（"截稿时点""数据未覆盖""扫描发现""本刊核查…未见""缺项/补回"）。逐处列行号。
4. 机器腔：框架句开头（"三点判断：""含义有四层："）、比喻套话（共同指向、外部前提、锚点、底盘、读数、筹码、就此定型、不再只是…而是…、值得注意的是、可以说、无疑）、自拟标签加引号、分号串联的长句（>75 字）。逐处列行号。
5. 篇幅预算：正文汉字 9000-10000；概述 ≤4 段每段 ≤220 字且不复述详情数字；关联速判每条 ≤3 句；每件摘录 ≤5 条；附录 ≤9 条。超的列出。
6. 评分表述：统一"N分"；无"—"；内部件日期栏"·内部"。
7. 业务边界：三板块；电力线不按储能/交易二分（写"电力业务项下储能项目"）；决策建议不写"X业务无关"；油价变动类零出现；scope_absent 维度（柴油/重卡/农村/高速/居住区私桩/V2G）出现时是否写成"需业务方裁定"而非"公司不做"或正面展开成业务场景。
8. 内部件规格：渠道价值一句在概述；"先行获取、未见公开刊发"；纪要类不点名个人、数字标"据交流"、口头口径不写成"文件规定"。
9. 层级：地方件无越级；区级件最多一句。
10. 解读质量：有增量判断不只复述；敢下结论；承接关系自然句；不重复上期判断句；缺席性断言有限定；比例分母写清。
11. 与上期的重复：上期已详析的件本期只简短提及。
12. 格式一致性：详情标题日期式、【政策信息】日期行写法、关键词行、[A 趁早行动]/[B 研究/跟进]/[C 跟踪] 标签用法。

输出格式（markdown）：
## D门审计报告
### 汇总 PASS N / WARN N / FAIL N
### FAIL（必改）  位置（章节/行号+原句片段）| 问题 | 建议改法
### WARN（编辑裁定）  同上
### PASS 项
### 与上期对照表  结构要素 | 上期 | 本期 | 结论

报告写成 <WD>/audit/D门报告.md，最终回复给出汇总数与全部 FAIL 条目。
```

## 六、精简自查脚本（写完 draft.md、起审计前跑一遍）

```python
import re
t = open("draft/draft.md", encoding="utf-8").read()
print("正文汉字", len(re.findall(r"[一-鿿]", t)))          # 目标 9000-10000
sents = re.split(r"[。；]", t)
print("超75字长句", sum(1 for s in sents if len(re.findall(r"[一-鿿]", s)) > 75
                        and not s.strip().startswith(("|", "#", "-", "**"))))
bad = ["P_2026", "INTERNAL_", "⭐", "「", "」", "vault", "bundle", "frontmatter", "pipeline", "slate",
       "采集", "数据侧", "本期截稿", "数据未覆盖", "扫描发现", "缺项", "补回",
       "三点判断", "四层", "共同指向", "共同定义", "外部前提", "锚点", "底盘", "读数", "筹码",
       "就此定型", "不再只是", "值得注意", "可以说", "无疑", "不难看出", "综上", "某种程度"]
for w in bad:
    if w in t: print("禁词:", w, t.count(w))
paras = [p for p in t.split("\n") if p.strip() and not p.startswith(("|", "#"))]
for n, p in sorted(((len(re.findall(r"[一-鿿]", p)), p[:40]) for p in paras), reverse=True)[:8]:
    print(f"{n:5d}  {p}")                                   # 最长的段，超 250 字的拆
```
