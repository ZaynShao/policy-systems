## 2. 全局规则(已由用户确认,原文照抄进 JSON 的 meta)

- **S1 准入(D1)**:官方原文即 S1,含市级政府/市级主管部门原文;窗内 `role=fact` 且 `tier=S1` 的节点 ≥3 条,其中至少 1 条国家或省级;多个城市的同类动作合并为 1 个独立簇。`issuer_level` 按原文机关填 国家/省/市。`meta.s1_admission_rule` 原文:"市级政府/市级主管部门原文算 S1;窗内 role=fact 且 tier=S1 的节点≥3 条,其中至少 1 条国家或省级;多个城市的同类动作合并为 1 个独立簇"。
- **锚点(D3)**:仍在生效的窗外上位文件可作锚点节点:`role=fact`、`tier=S1`、`out_of_window: true`、`after_t0: false`;只用于定阶段、措辞变化、历史类比;不计入"3 条"、不计温度、不计信号。`meta.anchor_rule` 原文:"仍在生效的窗外上位文件可作锚点节点(out_of_window=true),只用于定阶段、措辞变化、历史类比;不计入 3 条、温度、信号"。
- **温度与态度(D2)**:不要手算,跑 `python3 tools/temp_calc.py industries/<id>.json --write`。`meta.stance_rule` 原文:"只计 T0 前、非锚点节点;fact 贡献=推力符号×20×级别权重(S1 1.0/S2 0.8/S3 0.5/S4 0.5)×层级权重(国家 1.0/省 0.7/市 0.4)×时效权重(距 T0 ≤90 天 1.0/≤180 天 0.7/≤365 天 0.4),context 节点再×0.5;temp=求和四舍五入后夹在[-100,100];temp≥30 收紧风险(risk);temp≤-30 国家支持(support);收紧分与支持分绝对值各≥25 且 |temp|<30 为并存(mixed);其余观察中(watch)"。
- **档位(决策①)**:高度可能=独立簇≥3、权力层级≥2、算子 SUPPORTED≥3、主体与载体/期限明确、基率 n≥5;较大可能=簇≥2、SUPPORTED≥2、基率 n≥5;可能=满足较大可能条件但基率缺失(封顶),或簇≥1 且 SUPPORTED≥1 且有 S1 且基率 n≥5;其余观察;任一算子 COUNTER 降一档。独立簇=不同机关、不同层级或不同政策包的官方事实;转载/镜像/同文号不增簇。
- **概率**:每张卡 H1/H2/H0 都填 `p`(分析师主观概率,和为 1),页面折叠标"未校准";主显示是档位。
- **基率(D4)**:同机关或同类文件的历史样本,每样本两个日期 + URL;n<5 → `missing: true`,卡片档位封顶"可能";允许"代理基率"(邻近机关/同类载体)作补充说明,标 `proxy: true` + `proxy_note`,**不解除封顶**。
- **影响**:非能源行业只写 `impact.strategy / gr / compliance`;能源三行业(加油、充电、电力)另填 `impact.business` 引 `policy-vault/_meta/framework/business_strategy.yaml` 的信号 id。
- **过程**:`process.kind = "analyst_record"`;不伪造运行回执;`calibration` 无判定则 `null`。
- **社会要素**:只用统计局/部委/12328/事故通报等官方数据(S1/S2)与央媒评论(S2);舆情阅读量、热搜位次一律不用;每条 context 节点必须 `relation.to_fact_id` 挂到一条 fact 并写 trigger/amplify/suppress/background。
- **转载**:部委原文页定位不到、只有省厅/地方政府转载时,记 S2,`gaps` 写"原文页待补";同一件全国多处转载只算一个事件。
- **共用件**:2026 年政府工作报告(2026-03-05)、国办发〔2026〕14 号《国务院 2026 年度立法工作计划》(gov.cn/zhengce/zhengceku/202605/content_7068346.htm)多个行业会用,引用时用同一 URL,只计一个独立簇。
- **S5 陷阱**:搜索引擎里的"2026 ×× 新规""×月起实施""七部门发文"大量来自新浪/网易/搜狐自媒体,官方查无此文;凡"新规"必须回官方文章页核到文号或原文,否则退回记 S5 并写进 `process.retrieval.rejected`。评估阶段已抓到的实例:"2026 网约车七部门新规、抽成上限 27%、5-31 双证截止"。

## 3. 每个行业的工作步骤(顺序不能乱)

1. **检索与准入**。按第 8 节给的栏目与已知件起步;逐条打开原文,记 URL、抓取日、HTTP 状态、抓取方式、级别、层级。拉回/准入/退回全部登记到 `sources/<id>/retrieval_log.md`(一行一条:URL | 标题 | 日期 | 机关 | 判定 admit/reject | 原因),数量写进 `process.retrieval`。
2. **建时间链**。fact 与 context 分开;窗外上位文件按 D3 作锚点;T0 之后的标 `after_t0`;原文摘录不改字。每节点在 `sources/<id>/<node_id>.md` 存一段原文摘录 + 抓取记录(frontmatter:url、fetched_at、http_status、fetch_tool、title、issuer、issuer_level、docno、date、tier)。
3. **阶段判定与算子**。按 T0 前最新政策事实定阶段;四算子逐个给 SUPPORTED / COUNTER / NOT_APPLICABLE / EVIDENCE_MISSING,并列出用到的事实 id;`CROSS_SOURCE_COMBINATION` 要写清簇的划分。
4. **基率**。按 D4;样本清单进 `process.base_rate.samples`。
5. **写卡**。可证伪断言、H1/H2/H0 互斥、档位、p、时间窗(from ≥ T0)、验证日(window.to 后 15 天内)、失效条件、反证、`basis_fact_ids`(只指向 T0 前窗内 fact)、影响。
6. **温度**。`python3 tools/temp_calc.py industries/<id>.json --write`。
7. **审阅清单**(`process.review_checks` ≥5 项):每个断言字段能否回链;S4 是否单独支撑;社会要素是否被当依据;有无未回链数字;有无把预测写成事实;有无 S5;锚点是否被计入 3 条/温度。
8. **F 门**。起一个 subagent,拿 JSON 与 `sources/<id>/` 逐条打开 URL,核标题、文号、日期、机关、层级、摘录是否在原文中出现,输出 `industries/<id>.F门.md`(逐节点 PASS/FAIL/WARN + 基率样本逐条);FAIL 必改后重跑。
9. **校验与落盘**。`python3 tools/validate.py industries/<id>.json` 必须 0 ERROR;WARN 在 F门.md 里说明。落盘:`industries/<id>.json`、`industries/<id>.F门.md`、`sources/<id>/`。

## 4. 交付与验收(每个行业)

1. `validate.py` 0 ERROR;`temp_calc.py` 写回的 temp/stance 未被手改。
2. 窗内 S1 fact ≥3(含 ≥1 国家/省),否则 `meta.stops` 记停点并停下等用户。
3. 基率 n≥5 带双日期 URL,或 `missing=true` + 档位封顶。
4. 卡 ≥1;H 互斥可判定;p 齐;三维影响齐(能源加 business)。
5. `process.retrieval` 计数与 `retrieval_log.md` 一致;四算子齐且 SUPPORTED/COUNTER 有 fact_ids。
6. `F门.md` FAIL=0。
7. `sources/<id>/` 每节点一段原文摘录。
8. `meta.stance_rule / s1_admission_rule / anchor_rule` 三条原文齐;`group`、`t0` 与本文一致。
9. 做完一个行业就把 JSON 路径、validate 输出、F 门结果发用户,不攒到最后。

## 5. 停点(遇到就停,发用户,不自补)

- 窗内 S1 fact <3,或没有国家/省级件
- 基率 n<5(可以继续做并封顶,但要报告)
- 社会要素找不到带来源的材料(可以没有,不能编)
- 范围定义与实际材料对不上
- 任何只能用 mock 数字才能填的字段
- 需要 token、服务器或未授权的站点

## 6. 纪律

- 事实只来自打开过的原文;摘要、评论、AI 派生层、搜索摘要都不作事实源。
- 数字全部带出处;同一指标多口径并列写,不互相校正。
- 不 SSH、不碰生产、不代登平台;只有用户要求才 commit。
- 时间用绝对日期;中文为主,直接给结论;有不一致先指出再动手。
