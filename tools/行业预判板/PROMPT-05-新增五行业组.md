## 3. 每个行业的工作步骤(顺序不能乱)

1. **检索与准入**。按 §7、§8 给的栏目与已知件起步;逐条打开原文,记 URL、抓取日、HTTP 状态、抓取方式、级别、层级。拉回/准入/退回全部登记到 `sources/<id>/retrieval_log.md`(一行一条:URL | 标题 | 日期 | 机关 | 判定 admit/reject | 原因),数量写进 `process.retrieval`(`admitted` 要等于时间链非 pending 节点数,validate 会对)。
2. **建时间链**。fact 与 context 分开;窗外上位文件按 D3 作锚点;T0 之后的标 `after_t0`;原文摘录**不改字**,跳接用"……"。每节点在 `sources/<id>/<node_id>.md` 存一段原文摘录 + 抓取记录(可先写 JSON 再 `python3 tools/gen_sources.py <id>` 生成)。
3. **阶段判定与算子**。`stage` 按 T0 前最新政策事实定(方向/部署/征求意见/正式/实施/执法);四算子逐个给 SUPPORTED / COUNTER / NOT_APPLICABLE / EVIDENCE_MISSING,并列出用到的事实 id;`CROSS_SOURCE_COMBINATION` 要写清簇的划分。
4. **基率**。按 D4;样本清单进 `process.base_rate.samples`。
5. **写卡**。可证伪断言、H1/H2/H0 互斥、档位、p、时间窗(`window.from ≥ T0`,否则 WARN)、验证日(`window.to` 后 15 天内,validate 查)、失效条件、反证、`basis_fact_ids`(只指向 T0 前窗内 fact)、影响。每个行业 ≥1 张卡,建议 2–3 张;`next` 指向 T0 后最近的一个确定节点(征求意见截止日、施行日、试点期限等)。
6. **推力与温度**。按 §2 表逐节点填 `push`(软规则加 `push_weight: 0.5`),然后 `python3 tools/temp_calc.py industries/<id>.json --write`;不许手改 temp/stance。
7. **产业方向**。按 §2 D8 填 `direction`(`confirmed: false`)。
8. **审阅清单**(`process.review_checks` ≥5 项):每个断言字段能否回链;S4 是否单独支撑;社会要素是否被当依据;有无未回链数字;有无把预测写成事实;有无 S5;锚点是否被计入 3 条/温度;同线是否重复计方向。
9. **F 门**。起一个 subagent,拿 JSON 与 `sources/<id>/` 逐条打开 URL,核标题、文号、日期、机关、层级、摘录是否在原文中逐字出现,输出 `industries/<id>.F门.md`(逐节点 PASS/FAIL/WARN + 基率样本逐条 + validate 输出);FAIL 必改后重跑。
10. **校验与落盘**。`python3 tools/validate.py industries/<id>.json` 必须 0 ERROR;WARN 在 F门.md 里说明(`direction 为草拟` 这条 WARN 是预期的)。
