## 每个行业的工作步骤(顺序不能乱)

1. **检索与准入。** 观察窗 [T0−365 天, T0]。只从官方网站(部委、省级政府、gov.cn)和白名单媒体(新华社、人民日报、中国能源新闻网等)取材料;每条记 URL、抓取日、级别。拉回、准入、退回的数量与退回原因都记进 `process.retrieval`。S5 一律退回。
2. **建时间链。** 政策事实(`role=fact`)与社会要素(`role=context`)分开标,社会要素必须挂到某条事实并写触发/放大/抑制。原文摘录不改字。T0 之后的只能标 `after_t0`。
3. **阶段判定与算子。** 按 T0 前最新政策事实定阶段;四个算子逐个给 SUPPORTED / COUNTER / NOT_APPLICABLE / EVIDENCE_MISSING,并列出用到的事实 id。
4. **基率。** 找同机关或同类文件的历史样本(征求意见→印发、试点→扩围、处罚→出文等),每个样本要有两个日期和 URL。样本不足 5 个标 `missing=true`,卡片档位封顶「可能」。
5. **写卡。** 每张卡:可证伪断言、H1/H2/H0 互斥、档位、时间窗、验证日、失效条件、反证、`basis_fact_ids` 只指向 T0 前的 `fact` 节点。概率只作可选的主观概率,页面会标未校准。
6. **温度与态度。** 按全组统一的 `stance_rule` 算 `temp_calc`,和等于 `temp`。
7. **审阅清单。** 逐项自检:每个断言字段能否回链;S4 是否单独支撑了断言;社会要素是否被当成依据;有没有未回链的数字;有没有把预测写成事实。
8. **F 门。** 起一个 subagent,拿着你的 JSON 逐条打开 URL,核标题、文号、日期、机关、摘录,输出 PASS/FAIL/WARN 清单;FAIL 必改。
9. **落盘。** `state/行业预判板/industries/<id>.json`(过 schema 校验)、`state/行业预判板/sources/<id>/`(每条节点一段原文摘录 + 抓取记录)、`state/行业预判板/industries/<id>.F门.md`。

## 停点(遇到就停,发给我,不要自己补)

- 基率样本不足 5 个(可以继续做,但要告诉我并封顶档位)
- 社会要素找不到带来源的材料(可以没有,不能编)
- 需要预测服务的数据、token 或服务器
